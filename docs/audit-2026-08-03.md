# Audit Aplikasi - 2026-08-03

Audit ini dilakukan mengikuti konteks di `docs/session.md` (integrasi Portal Mitra Outlet dan
IndiHome) untuk mencari bagian aplikasi yang kurang pas atau bisa dibuat lebih efisien, tanpa
menambah infrastruktur baru yang tidak beraturan.

## Sudah diperbaiki di commit ini

### 0. `npm run build` gagal total di `main` (paling kritis)

`src/app/(hidden)/admin/belanja/voucher/page.tsx` memakai `useState`/`useEffect`/`useRef` tapi
tidak punya direktif `"use client"`, dan memakai `XLSX.utils.sheet_to_json<any>(...)` yang
melanggar rule `@typescript-eslint/no-explicit-any`. Kedua hal ini membuat `npm run build` gagal
kompilasi -- bukan cuma warning. Ini bukan bagian dari perubahan Portal Mitra/IndiHome yang
sedang berjalan; ini bug yang sudah ada di `main` sebelum audit ini dimulai (`git diff` terhadap
`HEAD` untuk file ini kosong selain normalisasi baris). Artinya build produksi saat ini rusak
sampai perbaikan ini dipasang. Ditambahkan `"use client"` di baris pertama dan tipe generic
`XLSX.utils.sheet_to_json` diganti ke `unknown[]`. Sudah diverifikasi `npm run build` lulus penuh
setelah perbaikan.

**File:** `src/app/(hidden)/admin/belanja/voucher/page.tsx`

### 1. Port docker-compose tidak sinkron dengan Dockerfile/.env

`Dockerfile` mengatur `ENV PORT=3011` dan `EXPOSE 3011` (sesuai `.env.example` dan default
`deploy.sh`), tetapi `docker-compose.yml` memetakan `"3000:3000"`. Jika image ini dijalankan lewat
`docker-compose up`, container tetap listen di port 3011 sementara host hanya membuka 3000 --
service tidak bisa diakses. Diperbaiki menjadi `"3011:3011"` agar satu konvensi port dipakai di
seluruh alur (env, Dockerfile, deploy.sh, docker-compose).

**File:** `docker-compose.yml`

### 2. `GET /api/admin/submissions` menarik seluruh tabel sebelum memfilter

Endpoint ini memuat seluruh `form_submissions` beserta relasi lengkap (`form.program`,
`form.fields`, `submissionValues.field`, `winner`) lalu memfilter `status` dan `programId` di
JavaScript setelah data ada di memori. Ini O(n) terhadap seluruh riwayat submission setiap kali
admin membuka daftar peserta/undian dengan filter apa pun, dan akan makin lambat seiring data
bertambah.

Filter `status` dan `programId` sekarang didorong ke level SQL (`where` pada query relasional
Drizzle, plus sub-query `dynamicForms` untuk `programId`), sehingga hanya baris yang relevan yang
ditarik dari database. Filter teks bebas (`search`) tetap di memori karena mencari lintas field
dinamis yang sudah di-join -- itu tidak bisa didorong ke SQL tanpa index full-text terpisah.

**File:** `src/app/api/admin/submissions/route.ts`

### 3. Sisa Prisma yang sudah tidak dipakai (`prisma/`) -- dihapus

Proyek ini sepenuhnya berjalan di atas **Drizzle ORM** (`drizzle-orm`, `drizzle.config.ts`,
folder `drizzle/`, semua `npm run db:*`). Paket `@prisma/client`/`prisma` bahkan sudah tidak ada
di `package.json`, dan tidak ada satu pun import `@prisma/client` di `src/`. Folder `prisma/`
(`schema.prisma`, `seed.ts`, `dev.db`) adalah peninggalan sebelum migrasi ke Drizzle -- dua sumber
kebenaran skema database dalam satu repo adalah contoh persis "infrastruktur tidak beraturan"
yang berisiko membingungkan kontributor baru. Dihapus setelah dikonfirmasi ke Anda; `npx tsc
--noEmit` tetap lulus setelahnya.

## Temuan yang butuh keputusan Anda (belum diubah)

Dua kelompok file berikut juga teridentifikasi mati saat audit, tapi Anda memilih untuk tidak
menghapusnya di sesi ini -- hanya dicatat di sini sebagai rekomendasi.

### A. Skrip debug lepas di root repo

`test-db.ts`, `test-query.ts`, `test-query2.ts`, `tmp_dump.ts` adalah skrip sekali-pakai untuk
men-debug data form submission secara manual (query langsung ke Drizzle lalu `console.log`).
Tidak direferensikan dari `package.json` scripts maupun dari kode aplikasi mana pun, tapi karena
`tsconfig.json` meng-include `**/*.ts`, keempatnya ikut di-typecheck setiap build. Rekomendasi:
hapus, atau jika masih dipakai untuk debugging manual, pindahkan ke folder `scripts/debug/` yang
di-`.gitignore`-kan supaya tidak tercampur dengan source aplikasi.

### B. Fitur "outlet" lama yang sudah di-stub tapi belum dihapus

- `src/app/(hidden)/admin/outlet/page.tsx` -- isinya cuma komentar `// This file has been removed`
  dan `return null`.
- `src/app/api/admin/outlets/route.ts` dan `src/app/api/admin/outlets/[id]/route.ts` -- isinya
  cuma `// Outlet feature removed` dan mengembalikan array kosong / status 410.

Fitur outlet lama ini sudah digantikan oleh Portal Mitra Outlet (`/admin/mitra/outlet`,
`/api/admin/mitra/outlets`). Tidak ada bagian aplikasi lain yang memanggil route lama ini, tapi
karena filenya masih ada, Next.js tetap meng-generate route `/admin/outlet` dan endpoint API yang
membingungkan (terlihat seperti fitur aktif padahal cuma stub). Rekomendasi: hapus ketiga file
tersebut sepenuhnya, bukan sekadar di-stub.

### C. Dua jalur deployment yang tidak konsisten (tidak diubah)

`deploy.sh` men-deploy lewat PM2 langsung di VPS (`APP_DIR=/var/www/abkciraya.cloud`,
`PM2_NAME=abkciraya-web`), sementara `Dockerfile` + `docker-compose.yml` menyiapkan jalur
containerized yang terpisah dengan database MySQL sendiri di container. Catatan session.md juga
menegaskan proses produksi memakai `deploy.sh` + `npm run db:migrate`, bukan Docker. Belum jelas
apakah jalur Docker ini masih dipakai (mis. untuk staging) atau sisa dari percobaan awal. Ini
bukan bug yang saya perbaiki paksa -- hanya dicatat karena dua jalur deploy yang tidak
terdokumentasi mana yang "sumber kebenaran" adalah bentuk lain dari infrastruktur tidak beraturan.
Jika jalur Docker tidak lagi dipakai, sebaiknya dihapus; jika masih dipakai, sebaiknya
didokumentasikan kapan masing-masing jalur digunakan.

### D. Tidak ada index pada `form_submissions.form_id` / `.status`

`GET /api/admin/submissions` (lihat perbaikan #2 di atas) memfilter berdasarkan `status` dan
`form_id`, tapi tabel `form_submissions` di `src/db/schema.ts` tidak punya index di kolom
tersebut -- setiap query tetap full table scan di level MySQL walau filter sudah didorong ke SQL.
Menambah index butuh migrasi Drizzle baru (`drizzle-kit generate` + `db:migrate`) yang idealnya
diuji dulu terhadap database nyata; tidak dieksekusi di sesi ini karena MySQL lokal tidak aktif
saat audit ini dijalankan (konsisten dengan catatan di `docs/session.md`). Rekomendasi: tambahkan
index pada `form_id` dan `status` di migrasi berikutnya.

## Tidak diaudit mendalam

Cakupan aplikasi ini besar (E-commerce Belanja, Undian/Lottery, Portal Mitra Outlet, IndiHome,
Form Builder). Audit ini fokus pada temuan bernilai tinggi dan berisiko rendah untuk diterapkan
langsung. Modul Portal Mitra dan IndiHome yang baru diintegrasikan (lihat `docs/session.md`)
sudah melalui verifikasi build/lint/TypeScript sendiri saat dikembangkan dan tidak diperiksa
ulang secara terpisah di sini.
